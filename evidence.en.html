1 · The MVP V1

The Thor-Hub collects dual-screen mods and recomps for the AYN Thor in one place. Each mod has its own page. It says what you need to install it, whether it costs anything, whether the code is open and which issues are already known. The problem comes from D1: a lot of Thor owners find mods by chance on TikTok or Reddit and then get stuck installing them.

V1 has five mods: Dusklight (Twilight Princess), Pokémon Emerald, The Minish Cap, Call of Duty: Black Ops II (T6 Requiem) and Stardew Valley. I'm working alone, so I kept it at five for the first version.

The Hub page is the version you can try. You can search (typos are fine), open a mod page, tick off what you need and follow the button to the original source. Every known issue links to where it came from.

The install helper exists in two versions. It's switched off in this public GitHub Pages version, because the feature it uses to ask Claude only works inside a Claude artifact page. I have a test version with the helper there. The reason is explained under failed attempts.

Things V1 deliberately leaves out: user accounts, comments, hosting files and finding new mods automatically. That's how the backlog from 17 Nov puts it.

The install helper's prompt

The helper gets this text with every question (the original is in German). The current mod page as JSON and the question are attached below it.

You are the install helper of the Thor-Hub. Answer in [selected language], briefly and in a friendly, casual tone.
RULES:
- Use ONLY the KNOWLEDGE below. No general knowledge, no guessing, no other mods.
- If the question clearly matches a known issue with a fix: type="fix", reference=its id,
  steps=the fix steps of that entry.
- If it matches a known issue with status "open": type="open", reference=its id,
  explain that there's no fix yet.
- If it points to a requirement from "you need" that seems to be missing: type="fix", reference=null,
  steps name the missing requirement.
- If something is missing to tell entries apart: type="question" with exactly one short question.
- Otherwise: type="unknown". Don't make anything up.
- Never recommend downloads outside the original source, deleting saves
  or permanently turning off security features.
Reply ONLY with JSON: {"type":..., "reference":..., "text":..., "steps":[...], "question":...}

Why it looks like this:

  • Its knowledge is limited to the mod page. Wrong answers were my biggest worry in D2, and this way the helper can only repeat what's on the page.
  • The answer comes back as JSON. The page builds the display from it and never inserts the text as HTML. An issue only gets linked if that ID really exists on the page.
  • There are four answer types. "Open" was added because many real Minish Cap problems have an issue but no fix yet, and the helper should be able to say so without inventing one.
  • The safety rule is there because my threshold from D2 requires "no harmful instruction".

7 · Next test

The next test is the helper check (P1 in the backlog). It tests my biggest open question from D2: does the helper answer correctly?

How it works

  1. I write down 10 real problem cases with the expected answer. Some of them are deliberately not on the page, so I can check that it says "unknown". Minish Cap works best because it has the most real issues.
  2. I enter the cases into the helper in the artifact version and note every answer.
  3. Then a second person opens the link without my account and asks one of the questions. That settles K1 at the same time.

How I judge the result

At least 8 of 10 right and no harmful instruction: the helper stays, and I look for a way to offer it publicly. Below 6 of 10 or one badly wrong instruction: it goes, and the public version stays as it is here. In between, I do one round of prompt fixes and run it again.

After that comes the test with a person on a Thor (criterion 4). This GitHub Pages version is enough for it.
